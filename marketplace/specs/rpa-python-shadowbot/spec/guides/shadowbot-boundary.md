# ShadowBot / Python / Agent Boundary

## 核心判断

```text
依赖页面状态、登录或人工交互 -> 影刀
结构化、确定性、可测试、可复用 -> Python
需求澄清、代码、测试、文档、修复 -> Agent
业务确认、影刀开发、上线与验收 -> 用户
```

## 影刀负责

- 页面点击、输入、下载、上传和截图
- 登录、验证码、弹窗和人工确认
- 准备业务文件到约定输入目录
- 生成本次运行独立的 `input_{run_id}.json`
- 调用 `run.bat` 或 `runner.py`
- 读取 `runner_{run_id}.json` 并按 status 分支
- 实施重试、通知、调度和后续页面动作

## Python 负责

- 读取结构化输入和业务文件
- 数据校验、清洗、映射、计算、汇总和规则判断
- 写入稳定业务输出
- 分类业务异常和系统异常
- 输出 runner 结果、日志和异常快照
- 提供可复现、可自动测试的处理能力

## Agent 负责

- 从业务需求起草 input/type/payload/output/status 契约
- 在用户确认后实现 Python 业务代码
- 补充测试、示例和项目文档
- 基于 runner、日志、快照和脱敏样例定位问题
- 说明 Git 变化、验证证据、剩余风险和影刀接入项

## 用户负责

- 提供真实业务目标和优先级
- 确认输入输出契约
- 完成或调整影刀侧 UI 流程
- 提供必要的脱敏样例和运行证据
- 做业务验收、上线、合并和生产决策

## 放置逻辑的判断题

问以下问题：

1. 离开页面后，这段逻辑能否仅凭文件或 JSON 重现？能则偏向 Python。
2. 规则是否需要单元测试、版本追踪或跨项目复用？需要则偏向 Python。
3. 是否必须读取页面元素、处理验证码或等待人工？是则留在影刀。
4. 影刀是否正在承载复杂字段映射或多层判断？是则考虑迁移到 Python。
5. Python 是否试图控制未经约定的 UI 动作？是则退回边界讨论。

## 外部工具边界

- Trellis 或其他 Harness 管理 Agent 内部任务、记忆和 Spec，不进入 Python 运行依赖。
- 飞书 Base 展示业务、项目、任务、验收和运行事实，不保存 Agent 的每一步内部推理。
- Git 记录代码变化事实，不替代 runner 验证。
- runner 和影刀真实运行是执行结果的权威证据。

## 常见越界

- 把字段清洗和映射写成大量影刀条件分支。
- 为了方便 Agent，把 Trellis 状态写进 runner 协议。
- Python 代码直接依赖 Base 某条记录才能启动。
- Agent 未确认契约就同时修改 Python 和影刀流程。
- 用 Git 提交成功代替业务运行成功。
